📋 Pteam 直播與 KMS 錄影異常流程分析

問題根因：phqeteams08 (直播發起端) 與 phqeteams03 (前端 API 端) 之 appSettings.json 未同步，導致 MultiCall 記錄之 KMS 與實際寫入錄影檔的 KMS 不一致。

⚠️ 核心失敗原因： 錄影產檔程式依據 MultiCall.Kms 前往 KMS A 找檔，但前端實際串流至 KMS B 落盤 .webm，導致找不到檔案而轉檔失敗。

關鍵節點與分析說明

1. 設定不一致來源

主機 phqeteams08 與 phqeteams03 各自讀取本機的 appSettings.json。當維運人員修改了 08 但忘了同步更新 03 時，雙方指向不同的 KMS 實例。

2. 資料與實體檔案脫節

資料庫 MultiCall.Kms 記錄的是 08 所認定的 KMS A，但前端實際上連到 03 回傳的 KMS B 並儲存 .webm，產檔程式信賴 DB 資訊因此撲空找不到檔案。

3. 架構修復建議

• 根本解法：前端頁面應根據會議識別碼向 API 查詢 MultiCall.Kms，連線到該會議當初指定的 KMS。
• 組態解法：將各主機的 KMS 配置集中化管理，避免分散設定造成人工遺漏。
